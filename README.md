## 1. サービス概要（※最後に書いてOK）

本サービスは、同じ映画を複数回見た際の感想を、視聴日ごとに記録し
見比べられるサービスです。

映画は見るたびに新しい発見や感じ方の変化があるが、
これまでの感想を見返す手段がなく、変化に気づきにくいという課題があった。
本サービスでは視聴日ごとに感想を記録・一覧表示することで、
自分の感じ方の変化を振り返れるようにし、この課題を解決する。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

私自身、コロナ期にどんでん返し系の映画を見ていたときに一回目と二回目で振り返りたいと思う場合がありました。
でも、その時の変化を記録できないことが不便に感じていました。
このアプリでは、視聴ごとの感想を時系列で記録し、自分の感じ方の変化を楽しめます。

### 2-2. なぜそれが「気になった」のか

シックスセンスという映画を二回以上見たときに監督が残した細かな伏線を気づき、一回目では気づけなかったことに気づけたことで、自分の中の「 映画の見え方」が
変化していく感覚がありそれこそが映画をより面白いものに感じる要素だと思ったから

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

一回目見たときの感じ方と二回目見たときの感じ方が時間が経つにつれ忘れてしまい映画の見え方を書き留めることができない。

### 3-2. 本当に解決したい課題は何か

困りごと：感じ方の違いを後から書き留められない

- 感じ方の変化を誰かに共有できないから
- 自分がどう映画を見て感じたかを分かち合えないもやもや感が残る
- ほかの人との感じ方の違いが判らなくなり寂しい

→ 本当に解決したい課題：複数回映画を見た時の自分の感じ方の変化を書き留めておけないと、
後から他の人との感じ方の違いを比べられず、寂しさを感じてしまう

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

年齢設定：
  - 年齢：２０代
  - 理由：映画館の利用率が高くsnsなどの利用も苦にしない年代だから

生活・状況設定：
  - 生活・状況：一人暮らし
  - 理由：友達と映画の話をするときに使ってもらいたいから

環境設定：
  - 環境：新作は映画館、過去の名作は配信サービスで見返すことが多い
  - 理由：新作は公開期間が限られていて、大画面で見る価値があるため映画館で見る。
一方、過去の名作は映画館で上映していないことが多く、
自分のペースで何度も見返したいときは配信サービスを使う。

### 4-2. 自分とユーザーの距離

- 自分自身

→ 自分自身が新作は映画館、名作は配信で見返しており、
映画館では感想をすぐメモできずに忘れてしまい、配信で見返すときに前回の感想を思い出せなかったりする経験がある。
そのため、ユーザーが感じるであろう不便さを自分事として想像しやすい。

### 4-3. 実際に使われる可能性について(需要・存在確認)

最初に使ってくれそうな人：映画の感想をX/noteで発信している人

使う場面：複数回見たときの感情を見比べたいとき

代替手段：フィルマークス、note

置き換える理由：フィルマークスにもnoteにも、複数回視聴時の感情の変化を記録・見比べる機能がないため

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

- 配信で以前見た映画を見返そうとしたとき、「前に見たときどう感じたんだっけ」と思い出せず、記録しておけばよかったと感じた瞬間
- 映画タイトルを登録し、視聴日と感想を入力してもらう
- 同じ映画を2回目・3回目に見る前に、過去の感想を見返すことで「前回との感情の違い」を意識しながら視聴できる

## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査

最低1つは調べてください。

- サービス名：フィルマークス
- URL：https://filmarks.com/
- どんなことができるか：映画のレビューや星の数で評価することができる

### 5-2. それでも自分が作りたい理由

映画を二回目に見た後、フィルマークスに感想を書く際に、前回はどう感じたのか一回目の感想を見返したいと思った。
しかし、過去の感想を見るには投稿一覧をスクロールして探し出す必要があり、二つの感想を並べて見比べることができなかった。
探すだけでも手間がかかる上に、見比べながら書くこともできず、「これなら最初から記録しておけばよかった」と
もやもやした気分になった。

### 5-3. 差別化を「体験価値」で表現する

- 私のアプリの差別化ポイント：複数回映画を見た人が二回目を見た後感想を書く瞬間過去の感想その場を見比べられるので前回の感情の変化をすぐに確認できるアプリ

## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化

このサービスを使うことで、ユーザーはどう変化しますか？

- 行動の変化：今まではあいまいな感想を書く場合が多かったが見比べることができるようになることで書きやすくなる
- 気持ちの変化：自分の感情の変化を見比べられて面白く感じる、嬉しくなる
- 考え方の変化：一回目と二回目での映画の見方が変わる

### 6-2. 価値を一文で表す

このサービスは映画好きな人が過去の感想と見比べて感情や見方の変化を楽しめるようになるサービス

## 7. このアプリで実現すること

### MVPで作る機能

感想を記録する機能（CRUD）

### 本リリースで作る機能

## 8. このアプリの懸念点とその対策
※最低1つは必ず書いてください。

このアプリが**うまくいかない可能性**と、
それに対して**どう向き合おうとしているか**を書いてください。

### 懸念点①

- 何が問題になりそうか：感想を書くのがめんどくさくなる
- なぜそう思うか：時間がない人などは感想を書かなくなりそうだから
- そのために考えている対策：メモなど一言で書けるようにする

- 何が問題になりそうか：2回目の感想を書くタイミングを忘れてしまう
- なぜそう思うか：1回目を書いた後、見返す機会がないと忘れそうだから
- そのために考えている対策：本リリースでリマインド通知機能を検討する

## 9. 今後の展開・発展の方向性

このアプリは、
**「投稿して終わり」にならないために**
どんな広がりが考えられますか？

### 観点（すべて答えなくてOK）

- ユーザーはなぜ使い続ける？ 感想を見比べる機能があるから
- 続けることで何が変わる？　自分の感想の変化を感じ取れることでより映画が好きになる
- データが溜まると何ができる？　過去にどんな映画を見たのかすぐ振り返られる

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails
- DB：PostgreSQL
- デプロイ先：Render
- 使用予定ライブラリ：devise（ユーザー認証のため）、kaminari（一覧をページ分け）

### 10-2. 技術選定の比較検討

使用する技術を列挙するだけでなく、**なぜその技術を選んだのか**を比較して書いてください。

- 他にどんな技術を候補にしたか
- なぜその候補ではなく、この技術を選んだのか
- 不採用にした技術とその理由

| 候補 | 採用/不採用 | 理由 |
| --- | --- | --- |
| Ruby on Rails | 採用 | カリキュラムで学習済みで、CRUDをすぐに実装できる＋学習コストを抑えられる |
| Node.js(Express) | 不採用 | 学習コストが高く、MVPリリースまでの期間を優先した |
| PostgreSQL | 採用 | Renderでの無料デプロイと相性が良く、学習でも使ってきたため |
| MySQL | 不採用 | 機能的に大きな差はないが、学習実績があるPostgreSQLを優先した |
| Render | 採用 | 無料枠でデプロイ可能＋設定がシンプルでカリキュラムとの連携がしやすい |
| Heroku | 不採用 | 無料プランが廃止されており、個人開発では維持コストがかかる |
| devise | 採用 | Rails標準的な認証gemで、日本語の情報が豊富 |
| Sorcery | 不採用 | 最初の実装に書くコードの量や手間がDeviseより多くなるため |
- 今回チャレンジしたい点
感想を見比べる機能で、ユーザー体験を意識したUIを作りたい
- 不安な点
デプロイ後の動作確認でエラーが出た場合の切り分けに時間がかかりそう

### 10-3.キャッチアップ不足の懸念

本アプリのMVPでは、学習済みで確実に実装できるRails(View) + jQueryを採用した。React/Vueも検討したが、学習コストがかかり、MVPの開発期間内に完成できないリスクがあると判断し不採用とした。

今後の対処としては、本リリース後に通知機能からReactを試験的に導入し、学習と実践を並行して進める予定である。
